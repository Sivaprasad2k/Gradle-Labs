# Version 6: Recurring Jobs & Fixed-Rate Scheduling

## Overview
Version 6 adds support for recurring job execution via `RecurrencePolicy` and `FixedRateRecurrence`, enabling jobs to execute on a recurring fixed-rate schedule. V6 introduces explicit execution occurrence identities (`executionId`), missed-occurrence coalescing, schedule cancellation (`cancelRecurrence`), and strict isolation between retry attempts and recurrence occurrences.

---

## Key Features

### 1. Recurrence Architecture
- **Job Definition vs. Occurrences**: `Job` remains an immutable record definition holding an optional `RecurrencePolicy`. Each occurrence of a recurring `Job` produces an independent `JobExecution` occurrence.
- **Execution Identity**:
  - `Job.id()`: Stable job definition identifier (e.g. `heartbeat-job`).
  - `JobExecution.getExecutionId()`: Unique execution occurrence identifier (e.g. `heartbeat-job#1`, `heartbeat-job#2`).
  - `JobExecution.getOccurrenceNumber()`: 1-indexed occurrence count.

### 2. FixedRateRecurrence & Missed-Occurrence Coalescing
- **Scheduled Time Basis**: Next occurrence time is calculated from previous *scheduled* time $T_{scheduled}$, not completion time.
- **Coalescing Loop**:
  $$T_{next} = T_{scheduled} + k \cdot \text{interval} \quad \text{such that} \quad T_{next} \ge \text{now}$$
  Prevents backlog bursts or execution storms when worker execution is delayed.
- **No-Overlap Invariant**: At most one active execution instance of a recurring job exists in memory at any time.

### 3. Recurrence vs. Retry Separation
- **Retry**: Operates within a single `JobExecution` (e.g., attempt 1 $\rightarrow$ attempt 2).
- **Recurrence**: Creates a new `JobExecution` instance (e.g., `jobId#1` $\rightarrow$ `jobId#2`).

### 4. Schedule Cancellation & Workflow Controls
- `JobScheduler.cancelRecurrence(jobId)`: Prevents future recurrence occurrences while allowing running executions to finish.
- `FailurePolicy.CONTINUE`: Permanent failure of occurrence $k$ permits occurrence $k+1$.
- `FailurePolicy.HALT_SCHEDULER`: Permanent failure of occurrence $k$ halts scheduler and suspends future recurrence generation.
