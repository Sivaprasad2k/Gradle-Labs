# Version 1 (V1)

## Scope
Version 1 of the Job Scheduler is a foundational implementation focused entirely on the core logic of time-based scheduling. It is designed as a learning project to demonstrate clean architectural boundaries, Gradle builds, and unit testing of time-dependent code.

## Implementation Status
- **Complete**: Domain modeling (`Job`, `JobTask`).
- **Complete**: Priority-based scheduling using `PriorityQueue`.
- **Complete**: Sequential job execution.
- **Complete**: Testability using `java.time.Clock`.

## Explicitly Excluded Functionality
To maintain strict focus on the fundamental scheduling algorithm, the following features are intentionally omitted from V1:
- Concurrency, worker threads, or `ExecutorService` pools.
- Persistence mechanisms (e.g., PostgreSQL, Redis).
- Retry logic for failed jobs.
- Recurring jobs or cron expression support.
- Microservice infrastructure, REST APIs, or Web UI.
- Dependency injection frameworks (e.g., Spring).

## Limitations
- **Sequential Execution**: Because execution occurs on a single thread, any long-running job will inherently delay the execution of all subsequent jobs, regardless of their scheduled times.
- **Volatile State**: All registered jobs reside entirely in memory. If the application terminates unexpectedly, all pending jobs are lost.
- **Blocking Wait**: The scheduler utilizes `Thread.sleep()` to wait for future jobs, blocking the main thread from accepting new dynamic registrations during the sleep period (in a strictly sequential loop).

## Testing Strategy
The testing strategy focuses on behavioral verification using JUnit 5.
- The `java.time.Clock` abstraction is injected into the scheduler to allow tests to precisely control the flow of time without relying on slow or non-deterministic thread sleeps (where possible).
- Tests cover property validation, priority ordering, empty queue termination, and correct execution sequence.
