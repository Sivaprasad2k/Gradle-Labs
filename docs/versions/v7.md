# Version 7: Persistence, Execution History & Restart Recovery

## Overview
Version 7 introduces durable MongoDB persistence, execution history tracking, and restart recovery to the Java Job Scheduler. MongoDB functions as the durable single source of truth, while in-memory structures (`PriorityQueue`, `DependencyGraph`, `activeExecutions`) function as runtime projections reconstructed during startup.

---

## Key Features

### 1. MongoDB Durable Source of Truth
- **Collections**:
  - `jobs`: Durable Job definitions (`jobId`, `name`, `scheduledAt`, `taskType`, `taskPayload`, `dependencyIds`, `failurePolicy`, `recurrencePolicy`).
  - `executions`: `JobExecution` occurrences, lifecycle status, timestamps, and embedded `attempts[]` array.
  - `recurrence_states`: Recurrence metadata per job (`occurrenceCount`, `lastScheduledTime`, `scheduleCancelled`).
  - `scheduler_state`: Singleton document (`RUNNING`, `HALTED`, `STOPPED`).

### 2. JobTask Persistence Abstraction
- **TaskType & TaskPayload**: Replaces volatile Java lambdas with persistent String identifiers (`taskType`) and JSON parameter maps (`taskPayload`).
- **TaskRegistry**: Maps `taskType` to executable `TaskHandler` implementations upon restart.

### 3. Restart & Interrupted Worker Recovery
- **Interrupted Worker Recovery**: Any execution found in `RUNNING` status in MongoDB upon restart is transitioned to `FAILED` with `InterruptedWorkerException`, recording the attempt failure and evaluating `RetryPolicy`.
- **Missed Recurrence Coalescing**: Uses V6 fixed-rate coalescing relative to `clock.instant()` during restart recovery to avoid backlog bursts.
- **HALT Recovery**: If persisted state was `HALTED`, scheduler initializes in `HALTED` state until `resume()` is called.
